# 架构与数据修改约定

## 单一数据源

Room 是账本的单一持久化数据源。DAO 通过 Flow 提供账目、分类和设置；ViewModel 组合状态，Compose 仅呈现状态和发起操作。未使用网页容器。

数据修改走同一个 ViewModel，通过 Mutex 串行处理、Room 事务提交。UI 不直接改列表来假装保存成功。保存/删除成功后才退出对应页面；失败保留当前输入并给出提示。

## 账目类型

`income`、`expense`、`refund` 是独立的持久化类型。界面可把退款放在收入分类区，但保存时取分类自身的类型，不能通过中文名称判断，确保导入后自定义退款分类仍按退款处理。

`Entry.id` 在编辑时保持不变。退款的 `linkedExpenseId` 引用原支出，属于逻辑关联；每次保存和导入会校验完整数据的关联、日期及累计限额。删除原支出时检查关联退款，避免悬空关系。

## 汇总与渲染

当前余额使用所有历史数据及期初余额；月收入/支出只按月份筛选普通收支。图表在背景线程预计算日汇总和分类汇总，排除退款。退款状态索引也在后台生成，列表滚动时不反复扫描整本账目。

列表使用稳定 ID；折线图固定日间距并使用原生横向滚动。页面淡入淡出使用 Compose 帧时钟，没有独立固定帧率循环。

## 导入

文件选择器回传 URI 后，在 IO 线程限量读取、UTF-8 严格解码、解析 JSON 或 CSV，然后生成预览，不写数据库。

确认导入时重新读取当前数据库并重做合并/替换校验，防止预览后数据变化。完整恢复先生成内部恢复前备份，再在同一 Room 事务中替换账目、分类和设置；异常导致回滚。合并保留当前设置，相同 ID 内容冲突会整次阻止。

## 隐私与发布

应用没有网络权限、登录或埋点。系统自动云备份及设备迁移规则排除账本文件；用户主动导出的文件由其在系统文件选择器中选择保存位置。发布签名密钥不进入 Git、APK 或 CI。
